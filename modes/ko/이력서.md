# 모드: 이력서 -- ATS 최적화 PDF 생성

## 전체 파이프라인

1. `cv.md`를 진실의 원천으로 읽기
2. JD가 컨텍스트에 없으면 사용자에게 요청 (텍스트 또는 URL)
3. JD에서 15-20개 키워드 추출
4. JD 언어 감지 -> 이력서 언어 결정 (한국어 JD = 한국어 이력서)
5. 회사 위치 감지 -> 용지 포맷:
   - 미국/캐나다 -> `letter`
   - 한국 포함 그 외 -> `a4`
6. 역할 아키타입 감지 -> 프레이밍 적응
7. Professional Summary 재작성: JD 키워드 + 전환 내러티브 주입
8. 해당 채용공고에 가장 관련 높은 프로젝트 3-4개 선택
9. 경험 불릿 포인트를 JD 관련성 순으로 재정렬
10. JD 요구사항에서 역량 그리드 구성 (6-8개 키워드 구문)
11. 기존 성과에 키워드를 자연스럽게 주입 (절대 만들어내지 않음)
12. 템플릿 + 개인화 콘텐츠에서 전체 HTML 생성
13. HTML을 `/tmp/cv-candidate-{company}.html`에 작성
14. 실행: `node generate-pdf.mjs /tmp/cv-candidate-{company}.html output/cv-candidate-{company}-{YYYY-MM-DD}.pdf --format={letter|a4}`
15. 보고: PDF 경로, 페이지 수, 키워드 커버리지 %

## ATS 규칙 (깔끔한 파싱)

- 단일 컬럼 레이아웃 (사이드바 없음, 병렬 컬럼 없음)
- 표준 헤더 사용
- 이미지/SVG에 텍스트 넣지 않기
- PDF 헤더/푸터에 중요 정보 넣지 않기 (ATS가 무시함)
- UTF-8, 선택 가능한 텍스트 (래스터화 안 됨)
- 중첩 테이블 없음
- JD 키워드 분포: Summary (상위 5개), 각 직무 첫 불릿, Skills 섹션

## 한국어 이력서 섹션 헤더

한국어 JD인 경우 다음 섹션 헤더 사용:

| Placeholder | 한국어 | 영어 (원본) |
|-------------|--------|-------------|
| `{{SECTION_SUMMARY}}` | 프로페셔널 요약 | Professional Summary |
| `{{SECTION_COMPETENCIES}}` | 핵심 역량 | Core Competencies |
| `{{SECTION_EXPERIENCE}}` | 경력사항 | Work Experience |
| `{{SECTION_PROJECTS}}` | 프로젝트 | Projects |
| `{{SECTION_EDUCATION}}` | 학력 | Education |
| `{{SECTION_CERTIFICATIONS}}` | 자격증 | Certifications |
| `{{SECTION_SKILLS}}` | 기술 스택 | Skills |

## PDF 디자인

- **폰트**: Space Grotesk (제목, 600-700) + DM Sans (본문, 400-500) + Noto Sans KR (한글 폴백)
- **폰트 셀프호스팅**: `fonts/`
- **헤더**: 이름 Space Grotesk 24px 볼드 + 그라데이션 라인 `linear-gradient(to right, hsl(187,74%,32%), hsl(270,70%,45%))` 2px + 연락처 행
- **섹션 헤더**: Space Grotesk 13px, 대문자, letter-spacing 0.05em, 시안 프라이머리
- **본문**: DM Sans 11px, line-height 1.5 (한글은 1.6 권장)
- **회사명**: 퍼플 액센트 `hsl(270,70%,45%)`
- **마진**: 0.6in
- **배경**: 흰색

## 섹션 순서 (리크루터 6초 스캔 최적화)

1. 헤더 (큰 이름, 그라데이션, 연락처, 포트폴리오 링크)
2. 프로페셔널 요약 (3-4줄, 키워드 밀도 높게)
3. 핵심 역량 (6-8개 키워드 구문, flex-grid)
4. 경력사항 (역순)
5. 프로젝트 (관련성 높은 3-4개)
6. 학력 & 자격증
7. 기술 스택 (언어 + 기술)

## 키워드 주입 전략 (윤리적, 사실 기반)

합법적 재표현 예시:
- JD가 "RAG 파이프라인"이고 CV가 "LLM 워크플로우 with retrieval" -> "RAG 파이프라인 설계 및 LLM 오케스트레이션 워크플로우"로 변경
- JD가 "MLOps"이고 CV가 "관측성, evals, 에러 핸들링" -> "MLOps 및 관측성: evals, 에러 핸들링, 비용 모니터링"으로 변경

**후보자에게 없는 스킬을 절대 추가하지 않는다. 실제 경험을 JD의 정확한 어휘로 재표현만 한다.**

## HTML 템플릿

`cv-template.html`의 `{{...}}` 플레이스홀더를 개인화 콘텐츠로 대체:

| Placeholder | 내용 |
|-------------|------|
| `{{LANG}}` | `ko` 또는 `en` |
| `{{PAGE_WIDTH}}` | `210mm` (A4) 또는 `8.5in` (Letter) |
| `{{NAME}}` | (profile.yml에서) |
| `{{EMAIL}}` | (profile.yml에서) |
| `{{LINKEDIN_URL}}` | (profile.yml에서) |
| `{{PORTFOLIO_URL}}` | (profile.yml에서) |
| `{{LOCATION}}` | (profile.yml에서) |
| 섹션 헤더 | 위 한국어 섹션 헤더 테이블 참조 |
| `{{SUMMARY_TEXT}}` | 키워드가 포함된 맞춤 Summary |
| `{{COMPETENCIES}}` | `<span class="competency-tag">키워드</span>` x 6-8 |
| `{{EXPERIENCE}}` | 재정렬된 불릿의 각 직무 HTML |
| `{{PROJECTS}}` | 관련성 높은 3-4개 프로젝트 HTML |
| `{{EDUCATION}}` | 학력 HTML |
| `{{CERTIFICATIONS}}` | 자격증 HTML |
| `{{SKILLS}}` | 기술 스택 HTML |

## Canva CV 생성 (선택)

`config/profile.yml`에 `canva_resume_design_id`가 설정되어 있으면 선택지 제공:
- **"HTML/PDF (빠름, ATS 최적화)"** -- 위의 기존 플로우
- **"Canva CV (비주얼, 디자인 보존)"** -- Canva 워크플로우

`canva_resume_design_id`가 없으면 이 프롬프트를 건너뛰고 HTML/PDF 플로우 사용.

## 생성 후

채용공고가 이미 트래커에 등록되어 있으면: PDF를 해당 없음에서 있음으로 업데이트.
