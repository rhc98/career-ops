## 진실의 원천 (모든 평가 전 반드시 읽기)

| 파일 | 경로 | 시점 |
|------|------|------|
| cv.md | `cv.md` (프로젝트 루트) | 항상 |
| article-digest.md | `article-digest.md` (존재 시) | 항상 (상세 proof point) |
| profile.yml | `config/profile.yml` | 항상 (후보자 정보 및 타겟 역할) |
| _profile.md | `modes/_profile.md` | 항상 (사용자 아키타입, 내러티브, 협상) |

**규칙: proof point의 지표를 절대 하드코딩하지 않는다.** 평가 시 cv.md + article-digest.md에서 읽어온다.
**규칙: 아티클/프로젝트 지표는 article-digest.md가 cv.md보다 우선한다.**
**규칙: 이 파일을 먼저 읽고, _profile.md를 그 뒤에 읽는다. _profile.md의 사용자 설정이 이 파일의 기본값을 오버라이드한다.**

## 스코어링 시스템

평가는 6개 블록(A-F)으로 구성되며 글로벌 점수는 1-5점:

| 항목 | 측정 대상 |
|------|-----------|
| CV 매칭 | 기술, 경험, proof point의 정합성 |
| North Star 정합성 | 사용자의 타겟 아키타입(_profile.md)과의 부합도 |
| 보상 | 시장 대비 연봉 수준 (5=상위, 1=현저히 낮음) |
| 문화 시그널 | 기업문화, 성장성, 안정성, 원격 정책 |
| 레드플래그 | 블로커, 경고 사항 (감점 요소) |
| **글로벌** | 위 항목의 가중 평균 |

**점수 해석:**
- 4.5+ -> 강력한 매칭, 즉시 지원 권장
- 4.0-4.4 -> 좋은 매칭, 지원 가치 있음
- 3.5-3.9 -> 괜찮지만 이상적이지 않음, 특별한 이유가 있을 때만 지원
- 3.5 미만 -> 지원 비추천 (CLAUDE.md의 윤리적 사용 참조)

## 한국 시장 특화 (중요)

한국어 채용공고와 협상에서 글로벌 시장에 없는 고유 항목들이 있다. 이들을 반드시 정확하게 평가에 반영해야 한다:

| 항목 | 의미 | 평가 영향 |
|------|------|-----------|
| **4대보험** | 국민연금, 건강보험, 고용보험, 산재보험 | 정규직 기본. 미포함 시 강한 레드플래그 |
| **퇴직금** | 1년 이상 근무 시 30일분 평균임금 | 법정 의무. 별도 퇴직연금(DC/DB) 여부 확인 |
| **연봉 구조** | 기본급 + 성과급 + 인센티브 | 기본급 비중 확인. 성과급 비중 과도하면 리스크 |
| **주 52시간** | 법정 근로시간 (주 40시간 + 연장 12시간 상한) | 준수 여부 = 워라밸의 핵심 시그널 |
| **수습 기간** | 보통 3개월, 급여 최소 90% | 3개월 초과 시 확인 필요. 급여 삭감 폭 체크 |
| **스톡옵션** | 스타트업에서 흔함. 행사가, 베스팅 스케줄 확인 | IPO 가능성, 행사가 대비 기업가치 평가 |
| **식대** | 월 식대 (비과세 한도 20만원) | 소소하지만 실질 수입 영향 |
| **교통비** | 출퇴근 교통비 지원 | 하이브리드/출근 시 확인 |
| **자기개발비** | 교육/자격증/컨퍼런스 지원금 | 성장 의지를 보여주는 좋은 시그널 |
| **건강검진** | 연 1회 종합검진 | 복리후생 수준 지표 |
| **유연근무** | 재택/유연출퇴근/원격 | 한국은 아직 성장 중. "Full remote"는 드묾 |
| **연차** | 법정 15일 (1년차) ~ 25일 (max) | 15일 미만 = 위법. 20일+ = 좋음 |
| **정규직/계약직** | 고용 형태 | 계약직이면 전환 가능성 확인 |
| **인센티브/성과급** | PS(Profit Sharing), PI(성과 인센티브) 등 | 지급 기준, 실제 지급률 확인 |

### 한국 기업 유형별 평가 기준

| 유형 | 특징 | 평가 포인트 |
|------|------|-------------|
| **대기업** (삼성, LG, SK, 현대 등) | 안정성 높음, 체계적 프로세스, 수직적 조직 | 직급 체계, 승진 속도, 팀 문화, 야근 문화 |
| **중견기업** | 대기업과 스타트업의 중간 | 성장성, 업계 포지션, 워라밸 |
| **스타트업** (시리즈 A-C) | 빠른 성장, 높은 재량, 리스크 존재 | 투자 단계, 번아웃 리스크, 스톡옵션 가치, 팀 규모 |
| **외국계 한국 지사** | 글로벌 문화, 영어 사용 | 본사 vs 지사 의사결정 권한, 팀 독립성, 성장 기회 |
| **공공기관/공기업** | 높은 안정성, 정형화된 프로세스 | 연봉 테이블, 워라밸, 성장 한계 |

**성과급/인센티브 확인:**

### 위치 정책 (Location Policy)

**폼에서:**
- 실제 근무 가능 여부는 `profile.yml`의 정보를 따른다
- 자유 입력 필드에는 시간대 겹침과 출근 가능 여부를 명시

**평가 시 (스코어링):**
- 원격 항목에서 해외 하이브리드: 점수 **3.0** (1.0이 아님)
- "주 4-5일 출근 필수, 예외 없음"인 경우에만 1.0

## 글로벌 규칙

### 절대 하지 않는 것 (NEVER)

1. 경험이나 지표를 만들어내지 않는다
2. cv.md나 포트폴리오 파일을 수정하지 않는다
3. 후보자 대신 지원서를 제출하지 않는다
4. 생성 메시지에 전화번호를 포함하지 않는다
5. 시장 수준 이하의 보상을 추천하지 않는다
6. JD를 읽지 않고 PDF를 생성하지 않는다
7. 기업 관료체 용어를 사용하지 않는다
8. 트래커를 무시하지 않는다 (평가한 모든 채용공고는 등록)

### 항상 하는 것 (ALWAYS)

0. **자기소개서:** 폼에서 허용하면 항상 포함. CV와 동일한 디자인. JD 인용을 proof point에 매핑. 최대 1페이지.
1. 평가 전 cv.md, _profile.md, article-digest.md(존재 시) 읽기
1b. **세션 첫 평가:** `node cv-sync-check.mjs`를 Bash로 실행. 경고가 있으면 사용자에게 알림
2. 역할 아키타입을 감지하고 _profile.md에 따라 프레이밍 조정
3. 매칭 시 CV의 정확한 라인을 인용
4. WebSearch로 보상 및 회사 데이터 조사
5. 평가 후 트래커에 등록
6. 채용공고의 언어로 콘텐츠 생성 (한국어 공고 = 한국어 리포트)
7. 직접적이고 실행 가능한 내용 -- 빈말 없이
8. 자연스러운 한국어 테크 문체. 짧은 문장, 동작 동사, 수동태 최소화. 기술 용어는 영어 그대로 사용.
8b. PDF Professional Summary에 case study URL 포함 (리크루터가 summary만 읽을 수 있음). 모든 URL은 HTML에서 `white-space: nowrap`
9. **트래커 추가는 TSV로** -- applications.md를 직접 편집하지 않는다. TSV를 `batch/tracker-additions/`에 작성, `merge-tracker.mjs`가 병합
10. **모든 리포트 헤더에 `**URL:**` 포함** -- Score와 PDF 사이

### 도구

| 도구 | 용도 |
|------|------|
| WebSearch | 연봉 조사, 트렌드, 기업문화, LinkedIn 연락처, JD 추출 폴백 |
| WebFetch | 정적 페이지에서 JD 추출 폴백 |
| Playwright | 채용공고 활성 여부 확인 (browser_navigate + browser_snapshot). **절대 Playwright를 2개 이상 에이전트에서 병렬 사용하지 않는다** |
| Read | cv.md, _profile.md, article-digest.md, cv-template.html |
| Write | PDF용 임시 HTML, applications.md, 리포트 .md |
| Edit | 트래커 업데이트 |
| Canva MCP | 선택적 비주얼 CV 생성. 베이스 디자인 복제, 텍스트 편집, PDF 내보내기. profile.yml에 `canva_resume_design_id` 필요 |
| Bash | `node generate-pdf.mjs` |

### Time-to-offer 우선순위
- 작동하는 데모 + 지표 > 완벽함
- 빨리 지원 > 더 조사
- 80/20 접근, 모든 것에 타임박스

## 전문 작성 규칙 & ATS 호환성

PDF summary, 불릿 포인트, 자기소개서, 폼 답변, LinkedIn 메시지 등 후보자 대면 문서에 적용. 내부 평가 리포트에는 적용하지 않음.

### 한국어 문서에서 피할 표현
- "열정적인" / "결과 지향적" / "검증된 역량" (구체적으로 대체)
- "~를 레버리지 했습니다" ("~를 활용했습니다" 또는 도구 이름 직접 언급)
- "~를 선도했습니다" ("~를 이끌었습니다" 또는 "~를 주도했습니다")
- "시너지" / "로버스트" / "심리스" / "최첨단" / "혁신적"
- "빠르게 변화하는 시대에"
- "~하는 능력을 보유" / "베스트 프랙티스" (구체적인 방법 이름)
- 과도한 존칭이나 미사여구 (간결하고 프로페셔널하게)

### ATS를 위한 유니코드 정규화
`generate-pdf.mjs`가 em대시, 스마트 따옴표, 제로 너비 문자를 자동으로 ASCII로 정규화. 하지만 애초에 생성하지 않는 것이 최선.

### 문장 구조 다양화
- 모든 불릿을 같은 동사로 시작하지 않기
- 문장 길이를 섞기 (짧게. 그 다음은 맥락과 함께 길게. 다시 짧게.)
- 항상 "X, Y, Z" 패턴만 쓰지 않기 -- 때로는 2개, 때로는 4개

### 추상보다 구체
- "p95 레이턴시를 2.1초에서 380ms로 단축" > "성능을 개선"
- "12k 문서 위 Postgres + pgvector로 retrieval" > "확장 가능한 RAG 아키텍처를 설계"
- 허용 범위 내에서 도구, 프로젝트, 고객 이름을 명시
