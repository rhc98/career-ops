# 모드: 채용공고 -- 평가 A-F

후보자가 채용공고를 붙여넣으면 (텍스트 또는 URL) 항상 6개 블록을 모두 제공한다.

## 0단계 -- 아키타입 감지

채용공고를 6개 아키타입 중 하나로 분류 (`_shared.md` 참조). 하이브리드인 경우 가장 가까운 2개를 표시. 이것이 결정하는 것:
- 블록 B에서 어떤 proof point를 우선할지
- 블록 E에서 summary를 어떻게 재작성할지
- 블록 F에서 어떤 STAR 스토리를 준비할지

## 블록 A -- 역할 요약

테이블 구성:
- 감지된 아키타입
- 도메인 (Platform / Agentic / LLMOps / ML / Enterprise)
- 기능 (Build / 컨설팅 / 매니지먼트 / Deploy)
- 시니어리티
- 근무 형태 (풀 리모트 / 하이브리드 / 출근)
- 팀 규모 (언급된 경우)
- TL;DR 1줄 요약

**한국 시장 추가 항목:**
- 기업 유형 (대기업 / 중견 / 스타트업 / 외국계)
- 고용 형태 (정규직 / 계약직 / 인턴)
- 직급 (해당 시 -- 사원/대리/과장/차장/부장 등)

## 블록 B -- CV 매칭

`cv.md` 읽기. 채용공고의 각 요구사항을 CV의 정확한 라인에 매핑하는 테이블 작성.

**아키타입에 따라 적응:**
- FDE -> 빠른 전달과 고객 대면 proof point 우선
- SA -> 시스템 설계와 통합 경험 우선
- PM -> 프로덕트 디스커버리와 지표 우선
- LLMOps -> evals, observability, 파이프라인 우선
- Agentic -> 멀티에이전트, HITL, 오케스트레이션 우선
- Transformation -> 변화 관리, 도입, 확장 우선

**갭 섹션**: 각 갭에 대한 완화 전략 포함. 각 갭마다:
1. 하드 블로커인가, 우대사항(nice-to-have)인가?
2. 후보자가 인접 경험을 보여줄 수 있는가?
3. 포트폴리오 프로젝트로 이 갭을 커버할 수 있는가?
4. 구체적 완화 계획 (자기소개서 문구, 빠른 프로젝트 등)

## 블록 C -- 레벨 및 전략

1. **JD의 감지된 레벨** vs **해당 아키타입에서의 후보자 자연 레벨**
2. **"시니어로 포지셔닝" 계획**: 아키타입에 맞춘 구체적 표현, 강조할 성과, 경험을 강점으로 포지셔닝하는 방법
3. **"다운레벨 시 대응" 계획**: 보상이 공정하면 수용, 6개월 리뷰 협상, 명확한 승진 기준 요청

## 블록 D -- 보상 및 수요

WebSearch로 조사:
- 해당 역할의 현재 연봉 (Wanted, 잡코리아, 사람인, Blind Korea, 크레딧잡)
- 해당 기업의 보상 평판 (잡플래닛, Blind)
- 해당 역할의 수요 트렌드

데이터와 출처를 인용한 테이블. 데이터가 없으면 없다고 솔직하게 -- 만들어내지 않는다.

**한국 시장 -- 필수 확인 사항:**
- 연봉 구조: 기본급 / 성과급 / 인센티브 비율은?
- 4대보험 포함 여부 (정규직이라면 당연. 아니면 레드플래그)
- 퇴직금 별도 적립 여부 (DC형/DB형 확인)
- 스톡옵션: 있다면 행사가, 베스팅 스케줄, 최근 밸류에이션
- 식대/교통비/자기개발비 등 복리후생
- 수습 기간과 수습 중 급여 조건
- 정규직인지 계약직인지 (계약직이면 전환 가능성)

## 블록 E -- 맞춤화 계획

| # | 섹션 | 현재 상태 | 변경 제안 | 이유 |
|---|------|-----------|-----------|------|
| 1 | Summary | ... | ... | ... |
| ... | ... | ... | ... | ... |

CV 변경 Top 5 + LinkedIn 변경 Top 5 (매칭 최대화).

## 블록 F -- 면접 준비

6-10개 STAR+R 스토리를 JD 요구사항에 매핑 (STAR + **Reflection**):

| # | JD 요구사항 | STAR+R 스토리 | S | T | A | R | Reflection |
|---|------------|---------------|---|---|---|---|------------|

**Reflection** 칼럼은 배운 점 또는 다르게 할 점을 담는다. 시니어리티의 시그널 -- 주니어는 일어난 일을 설명하고, 시니어는 교훈을 추출한다.

**Story Bank:** `interview-prep/story-bank.md`가 있으면 이미 등록된 스토리인지 확인. 없으면 새로 추가. 시간이 지나면서 어떤 면접 질문에도 적응 가능한 5-10개 마스터 스토리 뱅크가 구축된다.

**아키타입에 따라 선택/프레이밍:**
- FDE -> 전달 속도와 고객 대면 강조
- SA -> 아키텍처 의사결정 강조
- PM -> 디스커버리와 트레이드오프 강조
- LLMOps -> 지표, evals, 프로덕션 강화 강조
- Agentic -> 오케스트레이션, 에러 핸들링, HITL 강조
- Transformation -> 도입, 조직 변화 강조

추가 포함:
- 추천 case study 1개 (어떤 프로젝트를 어떻게 발표할지)
- 레드플래그 질문과 대응법 (예: "왜 이직하시나요?", "팀 관리 경험이 있으신가요?", "연봉 기대치가 어떻게 되시나요?")

## 평가 후 작업

블록 A-F 생성 후 **항상** 수행:

### 1. 리포트 .md 저장

평가 전체를 `reports/{###}-{company-slug}-{YYYY-MM-DD}.md`에 저장.

- `{###}` = 다음 순번 (3자리, 앞에 0 채움)
- `{company-slug}` = 회사명 소문자, 공백 없이 (하이픈 사용)
- `{YYYY-MM-DD}` = 오늘 날짜

**한국 회사명 slug 규칙:** 파일명에는 ASCII만 사용. 한글 회사명은 로마자화:

| 회사명 | slug |
|--------|------|
| 네이버 | naver |
| 카카오 | kakao |
| 삼성전자 | samsung |
| 토스 (비바리퍼블리카) | toss |
| 당근마켓 | danggeun / karrot |
| 쿠팡 | coupang |
| 배달의민족 (우아한형제들) | baemin / woowa |
| 라인 | line |
| SK텔레콤 | skt |

공식 영문 브랜드명이 있으면 그것을 사용. 없으면 국립국어원 로마자 표기법 또는 통용 영문명 사용.

**리포트 포맷:**

```markdown
# 평가: {회사명} -- {역할}

**날짜:** {YYYY-MM-DD}
**아키타입:** {감지된 유형}
**Score:** {X/5}
**URL:** {채용공고 URL}
**PDF:** {경로 또는 대기 중}

---

## A) 역할 요약
(블록 A 전체 내용)

## B) CV 매칭
(블록 B 전체 내용)

## C) 레벨 및 전략
(블록 C 전체 내용)

## D) 보상 및 수요
(블록 D 전체 내용)

## E) 맞춤화 계획
(블록 E 전체 내용)

## F) 면접 준비
(블록 F 전체 내용)

## G) 지원 답변 초안
(score >= 4.5일 때만 -- 지원 폼 답변 초안)

---

## 추출된 키워드
(JD에서 ATS 최적화를 위한 15-20개 키워드 목록)
```

### 2. 트래커 등록

**항상** `data/applications.md`에 등록:
- 다음 순번
- 오늘 날짜
- 회사명
- 역할
- Score: 매칭 평균 (1-5)
- 상태: `Evaluated`
- PDF: 아직 없으면 해당 없음 (auto-pipeline이 생성했으면 있음)
- Report: 리포트 .md 링크 (예: `[001](reports/001-company-2026-01-01.md)`)

**트래커 포맷:**

```markdown
| # | Date | Company | Role | Score | Status | PDF | Report |
```
