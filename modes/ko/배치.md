# 모드: 배치 -- 대량 채용공고 처리

두 가지 사용 모드: **conductor --chrome** (실시간 포털 탐색) 또는 **standalone** (수집된 URL 스크립트 처리).

## 아키텍처

```
Claude Conductor (claude --chrome --dangerously-skip-permissions)
  |
  |  Chrome: 포털 탐색 (로그인 세션 유지)
  |  DOM 직접 읽기 -- 사용자가 실시간으로 확인
  |
  +- 채용공고 1: DOM에서 JD + URL 읽기
  |    -> claude -p worker -> report .md + PDF + tracker-line
  |
  +- 채용공고 2: 다음 클릭, JD + URL 읽기
  |    -> claude -p worker -> report .md + PDF + tracker-line
  |
  +- 완료: tracker-additions 병합 -> applications.md + 요약
```

각 worker는 깨끗한 200K 토큰 컨텍스트의 `claude -p` 자식 프로세스. Conductor는 오케스트레이션만 담당.

## 파일 구조

```
batch/
  batch-input.tsv               # URL 목록 (conductor 또는 수동)
  batch-state.tsv               # 진행 상태 (자동 생성, gitignored)
  batch-runner.sh               # standalone 오케스트레이터 스크립트
  batch-prompt.md               # worker용 프롬프트 템플릿
  logs/                         # 채용공고별 로그 (gitignored)
  tracker-additions/            # 트래커 라인 (gitignored)
```

## 모드 A: Conductor --chrome

1. **상태 읽기**: `batch/batch-state.tsv` -> 이미 처리된 것 확인
2. **포털 탐색**: Chrome -> 검색 URL
3. **URL 추출**: DOM 결과에서 URL 목록 -> `batch-input.tsv`에 추가
4. **각 대기 URL에 대해**:
   a. Chrome: 채용공고 클릭 -> DOM에서 JD 텍스트 읽기
   b. JD를 `/tmp/batch-jd-{id}.txt`에 저장
   c. 다음 REPORT_NUM 순번 계산
   d. Bash로 실행:
      ```bash
      claude -p --dangerously-skip-permissions \
        --append-system-prompt-file batch/batch-prompt.md \
        "이 채용공고를 처리하세요. URL: {url}. JD: /tmp/batch-jd-{id}.txt. Report: {num}. ID: {id}"
      ```
   e. `batch-state.tsv` 업데이트 (completed/failed + score + report_num)
   f. `logs/{report_num}-{id}.log`에 로그
   g. Chrome: 뒤로 가기 -> 다음 채용공고
5. **페이지네이션**: 채용공고 없으면 -> "다음" 클릭 -> 반복
6. **완료**: `tracker-additions/` 병합 -> `applications.md` + 요약

## 모드 B: Standalone 스크립트

```bash
batch/batch-runner.sh [OPTIONS]
```

옵션:
- `--dry-run` -- 대기 목록만 표시, 실행 안 함
- `--retry-failed` -- 실패한 것만 재시도
- `--start-from N` -- ID N부터 시작
- `--parallel N` -- N개 worker 병렬 실행
- `--max-retries N` -- 채용공고당 시도 횟수 (기본: 2)

## batch-state.tsv 포맷

```
id	url	status	started_at	completed_at	report_num	score	error	retries
1	https://...	completed	2026-...	2026-...	002	4.2	-	0
2	https://...	failed	2026-...	2026-...	-	-	에러 메시지	1
3	https://...	pending	-	-	-	-	-	0
```

## 재개 가능성

- 중단 시 -> 재실행 -> `batch-state.tsv` 읽기 -> 완료된 것 건너뜀
- 잠금 파일(`batch-runner.pid`)로 중복 실행 방지
- 각 worker는 독립적: #47 실패해도 나머지에 영향 없음

## Worker (claude -p)

각 worker는 `batch-prompt.md`를 시스템 프롬프트로 받음. 자체 완결적.

Worker 출력:
1. Report `.md` in `reports/`
2. PDF in `output/`
3. 트래커 라인 in `batch/tracker-additions/{id}.tsv`
4. stdout으로 JSON 결과

## 에러 관리

| 에러 | 복구 |
|------|------|
| URL 접근 불가 | Worker 실패 -> conductor가 `failed` 마킹, 다음으로 |
| 로그인 필요 JD | Conductor가 DOM 읽기 시도. 실패 시 -> `failed` |
| 포털 레이아웃 변경 | Conductor가 HTML을 추론하여 적응 |
| Worker 크래시 | Conductor가 `failed` 마킹, 다음으로. `--retry-failed`로 재시도 |
| Conductor 중단 | 재실행 -> state 읽기 -> 완료된 것 건너뜀 |
| PDF 실패 | Report .md는 저장됨. PDF만 대기 |
