# 모드: 스캔 -- 포털 스캐너 (채용공고 발굴)

설정된 채용 포털을 스캔하고, 제목 관련성으로 필터링하여, 새 채용공고를 평가 파이프라인에 추가한다.

## 실행 권장 방식

메인 컨텍스트를 소모하지 않도록 서브에이전트로 실행:

```
Agent(
    subagent_type="general-purpose",
    prompt="[이 파일 내용 + 구체적 데이터]",
    run_in_background=True
)
```

## 설정

`portals.yml` 읽기:
- `search_queries`: `site:` 필터가 포함된 WebSearch 쿼리 목록 (광범위 발굴)
- `tracked_companies`: `careers_url`이 있는 특정 기업 목록 (직접 탐색)
- `title_filter`: 제목 필터링용 positive/negative/seniority_boost 키워드

## 발굴 전략 (3단계)

### 1단계 -- Playwright 직접 탐색 (주력)

**`tracked_companies`의 각 기업:** `careers_url`로 Playwright 탐색 (`browser_navigate` + `browser_snapshot`), 모든 채용 목록 읽기, 제목 + URL 추출. 가장 신뢰성 높은 방법:
- 실시간 페이지 (Google 캐시가 아님)
- SPA에서도 작동
- 새 채용공고 즉시 감지

### 2단계 -- Greenhouse API (보조)

Greenhouse 사용 기업은 JSON API (`boards-api.greenhouse.io/v1/boards/{slug}/jobs`)로 구조화된 데이터 획득. Playwright보다 빠르지만 Greenhouse 한정.

### 3단계 -- WebSearch 쿼리 (광범위 발굴)

`site:` 필터 쿼리로 포털 전체를 횡단 검색. 아직 `tracked_companies`에 없는 새 기업 발견에 유용하지만 결과가 오래되었을 수 있음.

**실행 우선순위:**
1. 1단계: Playwright -> `careers_url`이 있는 모든 `tracked_companies`
2. 2단계: API -> `api:`가 있는 모든 `tracked_companies`
3. 3단계: WebSearch -> `enabled: true`인 모든 `search_queries`

레벨은 가산적 -- 모두 실행 후 결과를 합치고 중복 제거.

## 워크플로우

1. **설정 읽기**: `portals.yml`
2. **이력 읽기**: `data/scan-history.tsv` -> 이미 본 URL
3. **중복 소스 읽기**: `data/applications.md` + `data/pipeline.md`

4. **1단계 -- Playwright 스캔** (3-5개씩 배치 병렬):
   각 기업의 `careers_url`로 탐색, 채용 목록 추출

5. **2단계 -- Greenhouse API** (병렬):
   `api:` URL에서 JSON 획득

6. **3단계 -- WebSearch 쿼리** (병렬):
   각 검색 쿼리 실행, 결과에서 제목/URL/회사 추출

7. **제목 필터링** (`title_filter` 사용):
   - `positive` 키워드 중 최소 1개가 제목에 포함 (대소문자 무관)
   - `negative` 키워드는 0개여야 함
   - `seniority_boost` 키워드는 우선순위를 높이지만 필수는 아님

8. **중복 제거** (3개 소스 대비):
   - `scan-history.tsv` -> 정확한 URL 중복
   - `applications.md` -> 회사 + 역할 정규화 이미 평가됨
   - `pipeline.md` -> 대기/처리됨에 이미 있는 URL

9. **WebSearch(3단계) 결과 활성 여부 확인** -- pipeline 추가 전:
   
   WebSearch 결과는 오래되었을 수 있음. 3단계 URL은 Playwright로 활성 여부 확인:
   a. `browser_navigate`
   b. `browser_snapshot`
   c. 분류:
      - **활성**: 직무 제목 + 설명 + 지원 버튼 보임
      - **만료**: "채용이 마감되었습니다" / 404 / 콘텐츠 없음
   d. 만료 시: `scan-history.tsv`에 `skipped_expired`로 기록 후 제외

10. **필터 통과한 새 채용공고**:
    a. `pipeline.md` "대기" 섹션에 추가: `- [ ] {url} | {company} | {title}`
    b. `scan-history.tsv`에 기록: `{url}\t{date}\t{query_name}\t{title}\t{company}\tadded`

11. 제목으로 필터된 것: `skipped_title`로 기록
12. 중복: `skipped_dup`로 기록
13. 만료: `skipped_expired`로 기록

## 한국 채용 포털 URL 패턴

| 포털 | URL 패턴 | 비고 |
|------|----------|------|
| **Wanted** | `wanted.co.kr/wd/{id}` | 잘 구조화됨, Playwright 추천 |
| **잡코리아** | `jobkorea.co.kr/Recruit/GI_Read/{id}` | 일부 JD가 이미지 |
| **사람인** | `saramin.co.kr/zf_user/jobs/relay/view?rec_idx={id}` | WebFetch 가능 |
| **점핏** | `jumpit.saramin.co.kr/position/{id}` | 개발자 전문, Playwright 추천 |
| **로켓펀치** | `rocketpunch.com/jobs/{id}` | 스타트업 중심 |
| **LinkedIn Korea** | `linkedin.com/jobs/view/{id}` | 로그인 필요할 수 있음 |

## careers_url 관리

**`careers_url` 없는 기업:**
1. 알려진 플랫폼 패턴 시도 (Ashby, Greenhouse, Lever 등)
2. 실패 시 WebSearch: `"{회사명}" 채용 careers`
3. Playwright로 확인
4. **발견한 URL을 portals.yml에 저장**

**`careers_url`이 404/리다이렉트:**
1. 출력 요약에 기록
2. `scan_query`로 폴백
3. 수동 업데이트 필요로 표시
