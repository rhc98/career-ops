# 모드: 파이프라인 -- URL 인박스 (Second Brain)

`data/pipeline.md`에 쌓인 채용공고 URL을 일괄 처리한다. 사용자가 URL을 수시로 추가하고, `/career-ops pipeline`으로 한꺼번에 처리.

## 워크플로우

1. **읽기**: `data/pipeline.md` -> "대기" / "Pending" / "Pendientes" / "En attente" 섹션에서 `- [ ]` 항목 찾기
2. **각 대기 URL에 대해**:
   a. 다음 `REPORT_NUM` 순번 계산 (`reports/` 읽어서 가장 높은 번호 + 1)
   b. **채용공고 추출**: Playwright (browser_navigate + browser_snapshot) -> WebFetch -> WebSearch
   c. URL 접근 불가 시 -> `- [!]`로 마킹하고 사유 메모 후 계속
   d. **auto-pipeline 전체 실행**: 평가 A-F -> 리포트 .md -> PDF (score >= 3.0) -> 트래커
   e. **"대기"에서 "처리됨"으로 이동**: `- [x] #NNN | URL | 회사 | 역할 | Score/5 | PDF 유무`
3. **3개 이상 대기 시**, 에이전트를 병렬로 실행 (Agent tool, `run_in_background`)하여 속도 최대화.
4. **완료 후**, 요약 테이블 표시:

```
| # | 회사 | 역할 | Score | PDF | 권장 액션 |
```

## pipeline.md 포맷

```markdown
## 대기
- [ ] https://www.wanted.co.kr/wd/123456
- [ ] https://www.jobkorea.co.kr/Recruit/GI_Read/12345678 | 회사명 | AI 엔지니어
- [!] https://private.url/job -- 오류: 로그인 필요

## 처리됨
- [x] #143 | https://www.wanted.co.kr/wd/789012 | 토스 | AI PM | 4.2/5 | PDF 있음
- [x] #144 | https://www.saramin.co.kr/zf_user/jobs/relay/view?rec_idx=12345 | 쿠팡 | SA | 2.1/5 | PDF 없음
```

> 참고: 섹션 헤더는 EN ("Pending"/"Processed"), ES ("Pendientes"/"Procesadas"), FR ("En attente"/"Traitees"), DE ("Offen"/"Verarbeitet"), KO ("대기"/"처리됨") 중 어떤 것이든 유연하게 인식. 쓸 때는 기존 스타일을 따른다.

## URL에서 채용공고 추출

1. **Playwright (우선):** `browser_navigate` + `browser_snapshot`. 모든 SPA에서 작동.
2. **WebFetch (폴백):** 정적 페이지이거나 Playwright를 사용할 수 없을 때.
3. **WebSearch (최후 수단):** 보조 포털에서 인덱싱된 JD 검색.

**특수 케이스:**
- **LinkedIn**: 로그인 필요할 수 있음 -> `[!]`로 마킹하고 후보자에게 텍스트 붙여넣기 요청
- **PDF**: URL이 PDF를 가리키면 Read 도구로 직접 읽기
- **`local:` 접두사**: 로컬 파일 읽기. 예: `local:jds/wanted-ai-pm.md` -> `jds/wanted-ai-pm.md` 읽기
- **Wanted** (wanted.co.kr): 잘 구조화된 JD. Playwright로 깔끔하게 추출 가능
- **잡코리아** (jobkorea.co.kr): 일부 JD가 이미지로 되어 있을 수 있음. 텍스트 추출 불가 시 후보자에게 알림
- **사람인** (saramin.co.kr): 구조화된 JD. WebFetch로도 대부분 추출 가능
- **점핏** (jumpit.saramin.co.kr): 개발자 전문 포털. Playwright 권장
- **로켓펀치** (rocketpunch.com): 스타트업 채용. Playwright 권장

## 자동 번호 매기기

1. `reports/`의 모든 파일 목록 조회
2. 접두사에서 번호 추출 (예: `142-medispend...` -> 142)
3. 새 번호 = 최대값 + 1

## 소스 동기화 확인

URL 처리 전 동기화 확인:

```bash
node cv-sync-check.mjs
```

비동기화가 발견되면 후보자에게 경고한 뒤 계속 진행.
