# 모드: 프로젝트 -- 포트폴리오 프로젝트 평가

6개 차원 스코어링 (1-5):

| 차원 | 가중치 | 5 = ... | 1 = ... |
|------|--------|---------|---------|
| 타겟 역할 시그널 | 25% | JD 스킬을 직접 증명 | 관련 없음 |
| 독창성 | 20% | 아무도 안 한 것 | 누구나 가진 것 |
| 시연 가능성 | 20% | 2분 라이브 데모 | 코드만, 비주얼 없음 |
| 지표 잠재력 | 15% | 명확한 지표 (레이턴시, 비용, 정확도) | 지표 측정 불가 |
| MVP까지 시간 | 10% | 1주 | 3개월 이상 |
| STAR 스토리 잠재력 | 10% | 트레이드오프가 풍부한 스토리 | 단순 구현 |

## "면접 팩" 요구사항

승인된 각 프로젝트:
1. **원페이저**: 제품 + 아키텍처 + 지표 + 평가 계획
2. **데모**: 라이브 URL 또는 2분 워크스루 녹화
3. **포스트모템**: 잘 된 것, 안 된 것, 완화책

## 80/20 계획

- 1주차 -> 핵심 지표가 있는 MVP
- 2주차 -> 다듬기 + 면접 팩

## 평결

- **구축** -> 주간 마일스톤이 있는 계획
- **스킵** -> 이유 + 대신 할 것
- **[대안]으로 피봇** -> 더 임팩트 있는 변형

**한국 시장 추가 고려:**
- GitHub 포트폴리오가 한국 테크 기업 채용에 미치는 영향
- 한국 기업에서 특히 어필되는 프로젝트 유형
- 한국어 기술 블로그/발표 자료의 가치
- 오픈소스 기여도의 국내 인식
